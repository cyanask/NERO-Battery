# 第三方试用范围与验收

本版面向有限范围的苹果芯片 MacBook 试用，不是多机型稳定版。CPU 与内存结果只代表原测试机和当时的窗口状态，不承诺比 AlDente 更低。

## 本次交付的验证范围

独立源码构建、ARM64 格式、ad-hoc 签名、逐文件清单、现有 Go 检查和普通账户只读发布预检，可在不改变当前充电控制的条件下验证。1.2.0 尚未在另一台干净 Mac 上完成首次安装、管理员交互、重启及卸载闭环；实际系统版本和硬件组合需逐台记录。

## 首轮人工验收

1. 记录芯片型号和 macOS 版本。确认无其他电池控制器运行；不要同时使用 AlDente、OpenDente 或原 batt 服务。
2. 解压并核对 SHA256，运行 `Check.command`，确认输出正确版本、ARM64 和当前账户，未接管充电。
3. 完成 `Install.command` 的系统认证，打开用户 Applications 中的 App。确认有菜单栏图标，关闭窗口后无 Dock 常驻图标，控制客户端空闲退出。
4. 连接电源，选择高于当前电量的合理上限，观察其正常充电并在达到上限时暂停。不要为了验收主动放电；需等待自然使用进入可观察区间。系统菜单可能仍显示“充电至 100%”，应结合 App 开关状态、`IsCharging` 和电流/净功率判断。
5. 自然使用后低于下限时恢复充电；检查上限、热保护设置及历史均保存在本机。不要通过加热设备验收热保护。
6. 正常合盖/唤醒和重启后，检查后台只有一份、设置保留、供电正常。睡眠本身不能执行定时任务，错过的任务不会补执行。
7. 仅设置“调整上限”这类不放电的定时任务，保持唤醒验证触发时间与去重行为。
8. 后台字节不变的前端维护版应可用 `Update-GUI.command` 更新；受保护组件变化必须拒绝免认证更新。
9. 运行 `Uninstall.command`，确认外接电源与充电开关交还 macOS、服务和组件移除，本地设置与历史保留。

本轮不安排手动放电或校准验收。界面保留这些显式操作，长流程尚有实机验证缺口；首轮试用请勿启用，也不要为其设置定时任务。原生快捷指令暂不可用，不作为已完成能力宣传。

反馈只需机型、系统版本、版本号、复现步骤及必要的脱敏状态。不要提交密码、序列号或整个应用支持目录。首台第三方闭环验收通过后，再扩大试用范围。
